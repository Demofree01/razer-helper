# 性能模式问题分析与 1.0.2 使用说明

本次面向 Blade 14 2025 / RZ09-0530 / PID 02C5；不把其他 Blade 型号的接口、功率或风扇限制直接用于本机。

## 为什么拔电再插电后拒绝切换

1.0.1 的保护检查只认识平衡 0、性能 2、安静 5。碰到其他模式时，为避免写入失败后无法恢复，主动拒绝切换，提示“当前模式无法安全回退”。这条提示来自 Helper，不是雷云、BIOS 或 Windows 宣告机器不能切换性能。

用户描述的操作是“退出雷云 → 拔电 → 再插电 → 重启 Helper”。雷云截图表明电池可以使用省电，接电可以使用自定义；开源协议中的省电代码为 6、自定义为 4，两者都被旧版遗漏。[模式枚举来源](https://github.com/blauzim/razer-ctl/blob/main/librazer/src/types.rs)

退出雷云后，电源变化可能让固件留下省电状态；原配置的 Blade 自动切换关闭，Helper 重启也不会主动应用接电预设。因此“接电但当前仍是省电 6”与用户的复现顺序及旧版报错逻辑吻合。报错当时没有保存原始模式；雷云重新打开后的读取是接电、模式 2。模式 6 是有代码与操作顺序支持的推断，不能把之后的模式 2 当成原报错现场记录。

1.0.2 纳入 4 和 6，并将接电与电池选项分开；接电时可以退出已有省电状态。还修正了旧设置页错误提供“电池安静”的选项。未知模式现在报告具体代码；持续两区不一致、手动风扇和不可回读的自定义状态仍会拒绝写入，并解释原因。

## 如何使用

在“性能 / 屏幕”选好两组预设，例如接电“性能”、电池“省电”。当前供电方式对应的“应用预设”按钮可立即切换；勾选“随插拔电源应用以上 Blade 预设”会在启动、唤醒或插拔时应用选定值。自动 Blade 切换默认关闭，保留用户原有开关，不会因为升级而开启。

自定义区提供 CPU 与 GPU 低、中、高。点击“应用自定义（接电）”会保存档位、将接电预设选为自定义并应用。只改下拉框会保存档位，点击应用或下次自动策略触发才写入。初次读取采用设备已有自定义记录；当前处于普通性能预设时，记录不代表当前正在按自定义功率工作。

Windows 电源 overlay 与 Blade 固件预设是两个独立控制层。接电性能不等于自动把 Windows 切到“最佳性能”；可以按需要分别选择。拔电自动 60 Hz 也有独立开关。

## 为什么没有照搬电压和风扇曲线

只读检查本机雷云日志 `RzAMDOverClock.log` 和 `RzAMDOverClockDLL.log`，看到 `GetCurveOptimizerValueAsync`、`SetCurveOptimizerValueAsync`、`SetCurveOptimizerForAllCores` 和 `SetCurveOptimizerBIOS`。这说明截图中的电压优化走独立 AMD 组件；与普通 HID CPU 档位不同。截图的“-30.000”不能据此解释成物理 -30 V，也不能直接套用其他开源项目的实验 CPU 档位 4。

本次没有加载或调用雷云 AMD DLL、安装驱动、访问 SMU 或写 BIOS。没有更改已有电压优化。未做独立电压读回，所以不声称已验证其数值。复刻这部分需要确认本机接口、单位、可靠读回与复原路径，不能通过试写未知参数探测。

固定风扇和曲线需要本型号转速范围、实时温度及后台退出或故障时可靠恢复。其他 Blade 的 2000–5000 RPM 范围不能直接视作这台机器的限制。现版本始终使用固件自动风扇，不能把旧雷云手动曲线完整回读时会要求先在雷云改为自动。

## 本次安全与验证

64 项离线测试通过，新增省电 6 残留在接电时的切换、失败后恢复 6、AC / DC 模式限制、自定义 CPU / GPU 部分失败复原、持续或瞬时两区差异、模式写入之间断电及 CPU 写入之后断电。

实机验证前保存性能快照为接电、性能 2、自动风扇 0、CPU 2、GPU 0。测试先使用原记录进入自定义，再把 CPU 降为 1、GPU 保持 0，回读成功后恢复 CPU 2、GPU 0、原模式 2。结果 `Passed=true`、`Restored=true`、`UnrelatedPreserved=true`，位于源码目录 `artifacts/performance-validation-1.0.2.json`。亮度、灯效记录、充电上限及 Fn 设备模式保持原值。实测没有改变电压，没有压力测试，也没有在你的其他应用中注入按键。

切换前快照和写入后的回读会发现多数竞争；Helper 的互斥不能约束雷云。如果雷云仍同时控制设备，参数可能被覆盖，请通过雷云自己的退出菜单正常退出。程序不结束雷云进程或禁用其服务。

更新后，用户在正常退出雷云后按原顺序拔电、插电、打开 Helper 并应用性能预设，回复“可以成功切换”。这属于原问题流程的人工实机确认，不等同于已经物理验证了事务写入途中断电或所有 GPU 档位。
