# Razer Helper

**中文** | [English](README.en.md)

轻量、离线的 Windows 托盘工具，用于控制雷蛇灵刃的键盘灯效、性能预设、刷新率、电池充电上限和本地宏。界面与托盘使用方式参考 [G-Helper](https://github.com/seerge/g-helper)，面向希望减少雷云后台依赖的用户。

**本程序的编制由 GPT - Sol 6.1 辅助完成。**

> **兼容性说明：目前仅在雷蛇灵刃 14 2025 款（Razer Blade 14 2025，RZ09-0530）上测试通过。即使是同型号、同类型或其他型号的机器，也不保证可以运行成功。BIOS、固件、驱动和系统版本差异都可能影响功能。进阶参数写入、真实 Fn／Hypershift 触发等尚未完成实机验证，不包含在“测试通过”的范围内。**
>
> **Compatibility: Tested only on the Razer Blade 14 (2025), RZ09-0530. Successful operation is not guaranteed on another unit of the same model, similar models, or different machines. Advanced parameter writes and native Fn/Hypershift triggering are not hardware-validated.**

遇到问题、需要适配其他机型或有建议，欢迎随时在 [GitHub Issues 留言](https://github.com/Demofree01/razer-helper/issues)。

## 下载与首次运行

1. 在 [Releases](https://github.com/Demofree01/razer-helper/releases) 下载 `RazerHelper-版本号-win-x64.zip`。GitHub 自动生成的 `Source code` 是源码，不能直接当作便携程序使用。
2. 将压缩包完整解压到一个固定目录，保留 `RazerHelper.exe.config`，运行 `RazerHelper.exe`。当前版本 **1.1.1**，需要 Windows x64 和 .NET Framework 4.8；实机测试系统为 Windows 11。
3. 在雷云托盘菜单正常退出 Synapse，避免同时覆盖灯效或性能。需要长期替代时，可自行在 Windows“启动应用”关闭雷云自启。Helper 不会结束雷云进程、禁用服务或卸载驱动。
4. 首次运行会保存可读取的原始状态，供“恢复初始设置”使用。先检查“性能／屏幕”页的供电状态、设备识别结果和内屏刷新率。
5. 关闭窗口会继续在托盘运行；托盘菜单的“退出”才会结束程序。“设置 → 登录 Windows 后在托盘启动”添加当前用户启动项，默认关闭。

运行不需要雷云、账号登录或联网。没有 WebView、遥测、自动更新器，也不捆绑第三方内核驱动。界面目前为中文，英文操作说明见 [English guide](README.en.md)。

**初始自动策略：**“拔电自动 60 Hz”默认开启，接电恢复所选刷新率；其他自动性能、电源模式、灯效恢复、背光保持和宏绑定默认关闭。接电刷新率优先采用首次读到的内屏当前值（高于 60 Hz 时），否则初始选择为 120 Hz。需要暂停时勾选“设置 → 暂停所有自动策略”。

## 性能、屏幕与能耗调节

### Blade 性能预设

在“性能／屏幕”分别选择接电和电池预设，点击与当前供电状态对应的“应用接电预设”或“应用电池预设”。只选择下拉框不会立即应用固件模式。

接电提供平衡、安静、性能、自定义；电池提供平衡、省电。需要自动切换时，勾选“随插拔电源应用以上 Blade 预设”，随后在启动、唤醒和供电切换时应用保存的预设。先手动确认可用，再开启自动策略。

自定义模式选择“CPU：低／中／高”和“GPU：低／中／高”，点击“应用自定义（接电）”。首次读取优先采用固件现有档位，这些记录只在自定义模式生效。档位由固件分配功率，**不等同于 15 W、30 W 等固定瓦数**。风扇由固件自动管理；雷云留下手动风扇状态时，先在雷云改回自动。

Windows“最佳能效／平衡／最佳性能”是独立的系统策略。Blade 性能模式不代表 Windows 一定同步切到最佳性能；自动 Windows 模式在“设置 → Windows 电源自动策略”单独启用。

无法读取可恢复的状态、未知模式、手动风扇或持续不一致会使写入被拒绝。失败时尝试恢复原值；切换途中拔电会停止接电专用写入，退回平衡并报告未完整恢复原接电状态。不要修改型号检查或发送未知命令绕过限制。

### 刷新率

“内置屏幕”只列出当前分辨率下驱动提供的刷新率。点击“60 Hz”或选择后点击“切换并确认”，画面正常时在 15 秒内确认；不确认时由独立进程尝试恢复原值。

“拔电自动 60 Hz；接电恢复所选刷新率”只控制内屏，不处理外接屏幕；复制显示、屏幕断开、未知供电状态或驱动拒绝时会跳过。测试机枚举到 48、60、75、100、120 Hz，其他机器以实际能力为准。

### 进阶能耗：先读取，手动应用

1. 打开“性能／屏幕 → 进阶能耗调节（手动）”，选择“接电参数”或“电池参数”。打开窗口和“只读刷新”不会写入。
2. 检查 Windows 模式和策略，编辑 CPU 最小／最大状态、睿频策略、EPP。最小值不得大于最大值。EPP 0 偏性能、100 偏节能；这些是 Windows 策略，**不是瓦数或电压**。
3. 只有点击“手动应用 CPU 策略”才写入。程序保存原值、检查状态，再应用并回读。Windows 保存的策略退出后仍存在；Helper 不在开机或插拔电源时重写这些进阶参数。
4. 撤销用“恢复上次 CPU 原值”。若其他程序已改变计划或数值，恢复会拒绝覆盖，请先核对备份。主界面的“恢复初始设置”不恢复进阶 CPU 策略。
5. “只读查询 GPU”读取 NVIDIA 信息。当前上限为 N/A、边界不完整或没有现有 NVIDIA 工具时，功率设置禁用。仅显示允许范围不足以证明可调，还需要可靠当前值建立回退快照。

本版本未在测试机上进行进阶 CPU／GPU 参数写入或压力测试。写入路径通过模拟测试，供用户之后手动验证。详见 [进阶能力与测试说明](docs/ADVANCED.md)。

## 键盘灯效

1. “键盘灯效”选择效果、颜色及方向，点击“应用灯效”。只改亮度时使用“仅应用亮度”。
2. 按需启用“启动／唤醒时应用已保存的灯效与亮度”或“电池时降低亮度”。
3. 闲置后渐暗熄灯、按键又亮起时，勾选“屏幕亮着时保持背光（避免闲置渐暗）”。约每三秒只读查询背光，不固定重写亮度，仍可用 Fn 手动调暗或关灯。锁屏、熄屏、变暗、睡眠或暂停时停止保持。
4. 退出雷云后原生 Fn 功能需要恢复时，可用“设置 → 启用原生 Fn”。这是固件模式恢复，**不代表启用了 Fn 宏**。

原生常亮 RGB 使用易失颜色帧，不保存自定义帧到闪存。熄灯或睡眠可能使帧丢失，需重新应用；“保持背光”不重新覆盖灯效。“灯效记录”是固件预设记录，不一定等于当前易失颜色，也不能完整恢复雷云复杂 Chroma 配置。

## 宏编辑、迁移与快捷键

### 新建或录制

在“宏 → 新建宏／编辑所选宏”设置名称、可选目标 EXE、运行上限及动作。支持延迟、键盘按下／释放、五个鼠标按钮、滚轮、相对／绝对移动、Unicode 文本、剪贴板文本、嵌套宏、循环、启动程序和运行命令，可调整顺序。

“3 秒后开始录制”仅在主动录制时捕获键盘、鼠标按钮和滚轮，最多 60 秒，Esc／F12 停止。普通录制不采集鼠标轨迹，轨迹可导入或编辑添加。宏内容和快捷键分别保存。

启动／命令需填 EXE 绝对路径和参数，不会自动生成 shell 命令。外部动作及手动剪贴板动作默认不允许，需逐个宏勾选权限；嵌套调用时外层与被调用宏都需允许。文本和参数在预览中默认隐藏，但实际内容会写入本地配置与导出文件。

### 从雷云迁移：只读扫描 → 预览 → 手动导入

1. 点击“只读扫描雷云宏”，读取本机缓存和宏日志，不修改、修复或锁定雷云数据库。
2. 查看名称、来源时间、动作数量和步骤。日志可能是历史快照，**不保证等于雷云界面里的最新版本**。文本和命令参数默认隐藏，可主动查看。
3. 勾选候选并导入。相同 ID 不覆盖；空宏、未知动作或不支持格式会拒绝。导入不会播放、启用绑定或授权外部动作。
4. 编辑器核对延迟、键码、鼠标坐标和目标 EXE，再自行绑定。

“导入 XML／JSON”支持 Helper JSON、已识别的雷云 4 `appEngine.events` JSON 和常见键鼠 XML；不保证全部历史格式兼容。1.1.1 将识别的雷云文本事件转为 Unicode 直接输入，修复旧版只写剪贴板却未输入文字的问题。手动“剪贴板”动作仍只写剪贴板，**不会自动粘贴**；需要另加粘贴按键和延迟，原内容含不可恢复的非文本数据时会拒绝执行。

### 先播放，再启用绑定

1. 准备普通文本输入框，选择宏，点击“3 秒后播放一次”，在倒计时结束前切换到目标窗口。
2. 保持目标前台窗口；焦点变化、锁屏、超时、输入失败或 F12 停止播放。停留在 Helper 时不会向自身输入。
3. 在“按键绑定 → Hypershift／自定义组合键”选择宏、按键和 **Ctrl+Alt**，选择播放一次、指定次数或再次按下停止，勾选“启用此绑定”，点击“保存并生效”。触发后释放 Ctrl、Alt 和触发键，避免修饰键影响模拟输入。
4. 旧式 Ctrl+Alt+F6–F11 可在“录制与快捷键”保存；同一组合键不要重复绑定，快捷键冲突会报错。

Fn 不是普通 Windows 修饰键。目前测试机没有可靠的独立 Fn 信号，**Fn／Hypershift 不能作为已完成的功能使用**。识别窗口用于研究和人工校准；无稳定、不同的按下／释放信号时保持 Fn 禁用，使用 Ctrl+Alt。“按住时播放”只提供给已校准 Fn，不支持 Ctrl+Alt 按住播放。

宏运行上限 1–600 秒；最多 64 个宏、单宏 4096 动作、嵌套 8 层、展开 100000 动作。停止时释放本次模拟按下的键／按钮。“宏动作已发送”只代表输入接口接受动作，不能证明目标程序已处理；高权限窗口、游戏输入机制、焦点、目标 EXE 和延迟都可能影响结果，Helper 不会自动提权。详见 [宏与 Fn 说明](docs/MACROS.md)。

## 配置、更新与恢复

本地文件位于 `%LOCALAPPDATA%\RazerHelper`，可用“设置 → 配置与日志”打开：

| 文件／目录 | 内容 |
|---|---|
| `settings.json` | 设置、宏、绑定和首次捕获的基线 |
| `settings.json.bak` | 上一次成功保存的配置 |
| `helper.log` | 轮转的控制／错误日志，不记录宏文本或命令参数 |
| `deleted-macros/` | 删除宏时保留的 JSON 备份 |
| `advanced/last-cpu-change.json` | 上次 CPU 手动策略的原值及应用后读数 |

**宏文本明文保存在配置、备份和导出文件中。请勿公开上传密码宏、完整配置或未经检查的雷云日志。** 发布包不含开发机器的配置、宏、日志或诊断快照。

更新前从托盘退出、备份本地配置目录，再解压新包运行。更换程序目录时，先在旧程序取消登录自启，再在新程序开启；原目录更新通常无需重新设置。退出不会自动撤销已应用的固件或 Windows 设置。

“恢复初始设置”先暂停自动策略，再尝试恢复首次捕获的 Windows 模式、同分辨率内屏刷新率、可恢复 Blade 预设、亮度、简单灯效、充电上限和 Helper 原自启状态。无法回读的复杂灯效、Fn 控制层等需另行恢复，不会声称复制了全部雷云配置。进阶 CPU 参数用独立恢复按钮。

卸载前取消登录自启并退出，再删除解压目录；需要保留宏时先备份配置。删除程序不会自动删除用户配置或恢复设备设置。

## 常见问题与留言

- **无法识别：** 硬件控制仅允许已识别的 RZ09-0530、USB `1532:02C5`，其他机型默认拒绝写入；通用 Windows 功能也受系统能力限制。
- **当前模式无法安全回退：** 正常退出雷云、在雷云中恢复自动风扇后再检查。1.0.2 已修复拔电省电状态残留、重新接电后的误拒绝；未知状态仍会拒绝。
- **宏有提示但无文字：** 使用 1.1.1 的直接“文本”动作，检查前台输入框、目标 EXE 和权限。手动“剪贴板”需另加粘贴按键，不要在 Helper 窗口里测试输入。
- **Fn 不识别：** 已知限制，先用 Ctrl+Alt；“启用原生 Fn”不是 Hypershift 实现。
- **参数／灯效被覆盖：** 检查雷云、Chroma、其他控制工具或自动策略是否冲突。
- **刷新率／GPU 瓦数不可用：** 以驱动能力和可靠回读为准，不强制启用隐藏选项。

欢迎随时在 [Issues](https://github.com/Demofree01/razer-helper/issues) 留言，中英文均可。反馈请提供机型／RZ 型号、BIOS、Windows 和 Helper 版本、是否接电、复现步骤、预期／实际结果及脱敏错误文字。不要上传密码、完整宏内容或账号信息。欢迎适配建议，但不承诺所有机器均可运行成功。

## 验证与源码构建

实机证据仅来自一台 Blade 14 2025：BIOS 1.06、键盘固件 1.4、Windows 11、Ryzen AI 9 365／RTX 5060 Laptop。基本模式、亮度、简单灯效指令、80%／充满、Windows 模式、60↔120 Hz 和显示回退有实机读数；闲置保持及“退出雷云 → 拔电 → 接电 → 切换性能”已由用户确认。实际颜色未用仪器测量，所有 CPU／GPU 档位组合、睡眠唤醒及全部目标程序未逐一实测。

1.1.1 通过 **120 项离线测试**；宏输入、外部动作、进阶写入和故障回退使用模拟接口。通过测试不代表全部功能已在硬件或目标程序验证。详见 [VALIDATION](docs/VALIDATION.md)、[PROTOCOL](docs/PROTOCOL.md)、[PERFORMANCE](docs/PERFORMANCE.md)。

在 Windows PowerShell 构建，无需 NuGet、额外 SDK 或第三方驱动：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build.ps1 -Tests
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/package.ps1
```

使用 Windows 自带 `Framework64/v4.0.30319/csc.exe`，目标为 C# 5／.NET Framework 4.8 x64；程序在 `dist/`，便携包在 `release/`。普通测试不改变硬件、不播放真实宏。

仓库的 Release 工作流在 GitHub Windows runner 构建、测试、打包，并发布版本 ZIP 与 SHA256。只在主分支的版本／发行说明／工作流变动或手动运行时触发，不在用户电脑自动运行；已有完整版本不会覆盖。发行说明须放在 `docs/releases/版本号.md`，程序不会自动检查更新。
